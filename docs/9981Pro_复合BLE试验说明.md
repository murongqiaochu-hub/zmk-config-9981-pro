# 9981 Pro 单服务键鼠＋手柄 BLE 试验

版本：**v2.3.3.4-ble-composite-trial.1** · 2026-10-30 · 板型bbp9981／9981 Pro（不是Air）。这是显式实验候选，不是稳定发布；**不自动刷写、不清配对、不擦设置、不改主机。** 原版说明书与历史UF2均保留。

## 01 这次解决什么

此前用户反馈键盘/鼠标正常、手柄不可用，并口头确认正在用键鼠回退11ee89e。本试验尝试用**同一个BLE HOG服务**提供键盘、消费键、鼠标和实验手柄，不再让主机发现两个独立HID服务；保持原有键鼠和灯控源码、USB与四层键图。

- 原196字节键鼠Map不动；新增手柄输入ID4／10字节正文、输出ID5／4字节正文，总Map380字节。BLE正文不额外带Report ID；USB仍是原9字节手柄body／10字节wire，不冒充改成同一协议。
- 手柄使用实验Stadia格式编码，但**不复制Google/Microsoft厂商身份，不是Stadia认证或原生Xbox XInput**。PnP、VID/PID、蓝牙地址配置不变，不保证iPadOS或具体App接受。
- 新订阅闸在收到本peer的OFF请求时立即阻止新的应用发送claim；发送仍须实际订阅有效、连接/路由/context一致。保留标准Zephyr CCC writer与恢复/地址/断连处理，不用破坏生命周期的wrapper。
- 连接回调与HOG使用同一个固定有界gate；reset不会覆盖更新的OFF，不会偷退仍在途的busy槽。原runtime的捕获连接引用、旧peer松键、USB和队列仍保留。

## 02 与上一纯BLE诊断版不同

本候选**不主动关闭BLE键盘、消费键或鼠标**，不要求只能测手柄。普通层继续键鼠，MEDIA层按原设计输出手柄；这不是承诺同一时刻所有层的按键都输出三种功能。保留键鼠是源码、主机回归及待验ARM的目标，是否在每种主机上实际正常必须实测。

试验基于已审源码配置，不是直接在用户11ee89e镜像上打补丁。默认键位以源码使用说明书v2.3.3.2为准：

| 操作 | 当前默认设计 |
| --- | --- |
| MEDIA W/D/Z/A | D-pad上/右/下/左 |
| MEDIA S/L | L3/R3独立按钮 |
| MEDIA O/K/Backspace/$ | Y/X/B/A |
| 左肩/右肩、通话/结束 | 数字LT/RT、LB/RB |
| MEDIA R/U | View/Menu；T/Y空 |
| 空格/触板机械按下 | Guide/Xbox，不是L3 |
| 触板、按住黑莓 | 相对位移虚拟左杆、临时右杆；停住手指不能保持倾斜 |
| SYM/右aA | 返回普通层；不改既有进入MEDIA的方法 |

UPPER Z仍是原五档位移增益0.6/0.9/1.2/1.5/1.8，保存语义、右aA与滚轮、灯控和按键均不新增或改绑。具体原操作见同批只读默认手册；不能拿更老键位说明替代。

## 03 哪些已经验证、哪些没有

- 新适配UBSan/ASan：完整Map/引用、stock键鼠LED、OFF预提交窗口、新ON等实际订阅、同值ON、最终epoch检查、peer/index复用、reset交错、busy在途所有权及独立生命周期TU均通过。
- 未改真实gamepad runtime的专项、19种action到10字节编码、实际队列与USB边界、独立runtime/HOG对象链接通过；整套host回归exit0（含32组CMake和旧反例）。这些仍是宿主测试，不是无线设备或目标ARM证明。
- **本说明首次提交时真实ARM尚待构建与ELF/UF2验收。** 最终交付仅以当日完成校验JSON和固件hash为准；若构建/来源/安全验收失败，不交付可刷件。不得把暂存源码或日志中的任意UF2当推荐件。
- 没有iPadOS GameController／`GCController.extendedGamepad`、官方Moonlight、Android、Mac或Windows的本轮实机结果，不宣称已修好兼容性，也不宣称送入SDK代表主机接收。

## 04 仍保留的试验限制

- 已claim的单个notify调用可以晚于OFF进入或返回；先前排入ATT的多个PDU不能撤回。SDK可能长时间等待，250/400ms应用队列期限不是SDK阻塞的硬上限，返回0不是主机ACK。
- 断连或退订后旧peer未必收到neutral/松键；订阅消失的EINVAL只改为既有有限重试，不能保证远端不卡键。切模式先松开按钮，不把强行重连当恢复保证。
- 不新增完整HOG suspend；保留stock控制点的已有语义，不称全协议合规。输出报告接受但忽略，无振动；扳机是数字0/255，Guide可能被系统截获。
- HID数据库/Map变化可能触发主机缓存问题，即使身份字段未变也不能保证免重配。**没有自动清配对/擦设置功能**，用户已有正常配对和键鼠优先。

## 05 用户决定开始后，最短实机顺序

1. 先确认最终交付JSON标记ARM/ELF/UF2验收通过，固件文件hash一致，并保存已核验回退11ee89e；未提供最终hash就不要刷。由用户本人决定何时手动刷入，Bot未操作设备。
2. 先用同一台设备检查普通层键盘输入、鼠标移动/左右键/滚轮和灯控；异常即停止，不连续试多台、不清设置。
3. 键鼠正常后进入原MEDIA层，检查系统是否出现控制器，再查按钮/方向和触板；记录主机型号、系统/App版本、USB还是BLE、对应槽位、固件hash与具体结果。
4. iPad先区分“能配对/看到HID服务”与“系统GameController接纳”。确认系统控制器后再看官方Moonlight；仅App未显示不能推断协议哪个字段出错。不要要求用户安装收费工具或无目的重复刷机。
5. 若要回退，使用同批核验的11ee89e原UF2，按用户熟悉的原手动方法恢复；不使用settings_reset、不擦NVS、不自动解除配对。若仅因HID缓存疑似不识别，先保存现象并暂停，另行决定是否允许目标主机重配；不保证回退自动消除所有缓存。
