## 02 候选设计，不是验证结论

这是一份**单 HOG 服务内复合报告**的源码设计：保留原有键盘、消费键、鼠标和 LED 报告路径，在同一个蓝牙 HID 服务中尝试加入手柄，而不是再注册第二个独立 HID 服务。**单服务、报告 ID 的安排以及键鼠保留均是设计与源级检查，不是实机验证或兼容承诺。**

| 蓝牙报告 | 候选设计 |
| --- | --- |
| 原键鼠及 LED | 原 stock 报告 Map 为 196 字节，原有 ID 1、2、3 的键盘/LED、消费键与鼠标项保留。 |
| 手柄输入 | Report ID 4，蓝牙报告正文 10 字节，不额外携带 ID 前缀；现有 9 字节状态经实验编码转换，并非直接把旧 9 字节当 10 字节发送。 |
| 手柄输出 | Report ID 5，正文 4 字节；只接受并忽略，不驱动振动，**无振动实现**。 |
| 复合 Map | 设计为 380 字节；追加手柄集合并显式设置方向帽的 Logical Minimum，避免继承旧鼠标范围。长度及模型检查不是设备读取或系统识别的证明。 |

## 04 订阅和排队：保护仍有空隙

候选尝试按捕获的连接、订阅、路由和代次约束发送，但**不是原子屏障**，以下问题尚未消除：

- 固定 SDK 的 CCC 写回调在新订阅值提交之前执行。即使回调先让旧代次失效，并发 worker 仍可能在 **precommit 窗口**取得新代次，却读到旧的订阅 ON 状态并尝试发送。没有原 CCC 条目时写 0 也可能不经过该回调。
- 最终 gate 检查与调用 SDK 之间仍有竞争窗口；先前已排队或聚合的多个 ATT PDU 不能靠代次撤回。不能把“最终门后一次提交窗口”误说成全链最多一帧。
- 向旧连接尝试发送 neutral / 松键，并不保证旧主机收到；SDK 接受或入队不是远端 ACK。断线、退订、队满、重连及重复提交时，不保证一定归中、不丢键或绝不卡键。
- 全局代次失效可能保守地清掉另一 peer 的待输入；重连、恢复和断连也不一定走逐 peer 写回调。原键鼠的共享通知标志及原控制点行为未因此声称修复；完整 HOG suspend 语义尚未实现。

这些边界来自固定 SDK 的源码审查及 host/mock 模型；真实 Zephyr 并发、加密、空口、连接切换与系统处理仍需分别验证，不能由模拟替代。

## 05 失败关闭、缓存和回退风险

候选对固定 stock 196 字节报告 Map 做**逐字节校验**；不一致时 HOG Report Map 读取会失败。此 fail-closed 检查只是源码保护：如果在设备中发生，理论上连键鼠 HID 枚举也可能受影响，**不代表设备安全或已验证可回退**。在未来另行授权的构建及实际 SDK、ARM/ELF 核验之前，不得将它当作可刷方案。

候选不改 PnP、VID/PID、蓝牙地址配置、配对或 settings，是源级设计；但 HID 数据库/报告 Map 变化仍**可能影响主机缓存或识别**，即使身份字段不变也不能排除。不会自动清配对；本轮也不清配对、不擦设置。不得把身份不变或现有键鼠正常，当作新数据库在任何设备上已经安全通过。

隔离暂存工具的设计会锁定候选、手柄 runtime、触板快照、两份键图等源码，并对固定 Zephyr 的 ATT/GATT 三文件设置字节一致性检查要求；这只是预备门槛，不是实际 SDK 已核验、ARM 已构建或设备已验收。任何未来尝试都应另行评估可恢复性与明确的回退路径，不用旧 UF2 冒充本候选。
