# 9981 Pro 纯 BLE 诊断候选补充说明

**说明书版本：v1.2（纯BLE诊断 P1 + PnP来源2用户测试反馈） · 日期：2026-10-28**

适用硬件：9981 Pro / P9981、bbp9981，非 9981 Air 键盘型号。**旧P1与Source 2分别通过真实ARM及静态验收；用户反馈本次Source 2实测“只有安卓手柄好用，其他键盘、鼠标、手柄都不行”。本次各项具体主机、传输和App未逐一提供，设备中实际刷入文件的哈希未独立核对；两个候选都不是三合一正式版。**

## 1. 先看限制：蓝牙只有实验手柄

本说明针对显式生成的纯 BLE 诊断候选，不替换原版默认固件，也不表示设备已经安装此候选。

- **候选关闭蓝牙键盘、Consumer（如音量/媒体键）和鼠标输出。** 公共发送入口拒发（ENOTSUP），并非只在 MEDIA 层关闭；退出 MEDIA 也不会恢复蓝牙键鼠。
- BLE 的 **HID 部分**只呈现实验 Game Pad，其他必要服务仍保留，用于分模式排查系统手柄识别；**不是键盘＋鼠标＋手柄蓝牙三合一**，没有新增运行时“纯手柄/三合一”切换 UI。
- **USB 源码、配置和原有接口未改，旧P1和Source 2均已编译，但两个候选均待设备回归。** “未改”不等于 USB 键鼠/手柄已经在候选上验证正常，也不保证可用 USB 随时救场。
- 保留现有键图、本地控制、板定义与设置项；不复制 Google/Microsoft VID/PID，不宣称 Stadia 认证、原生 Xbox/XInput 或 iPad 已兼容。可选PnP对照保留同一 `1D50:615E` 数值，但改变蓝牙PnP编号来源这一身份元数据，详见第8节；旧P1不变。
- 旧P1和Source 2实际编译配置均保留默认名 `bbp9981`、USB/PNP VID:PID `1D50:615E`、**GAP Appearance=961（键盘外观）**；运行时名称及空口状态尚未核验。“纯手柄”特指HID报告与服务，不代表通用外观类别也已更改。图标不能作为系统手柄识别证据；通用Gamepad外观类别是否影响iPad识别尚未测试。
- 默认四层、触板、轻拍、灯光、持久化和维护键沿用[默认使用说明书](<9981Pro_使用说明书.md>)，**发生冲突时，本说明的蓝牙输出限制、候选状态和本轮回退边界优先**。原手册中蓝牙键鼠已通过的记录属于原版，不能移作本候选结论。

依据：[实验与候选接线说明](<../experiments/gamepad_protocol/README.md>)、[候选生成器](<../tools/stage_pure_gamepad.py>)。默认生成器只在源树外的新目录复制并机械替换两份 CMake 接线；可选来源2对照再追加一项PnP配置。生成器不构建、不上传、不运行 Actions、不配对、不刷写。

## 2. 选择 BLE 与进入 MEDIA：仍用现有控制

以下按[默认手册第 4、14、17、18 章](<9981Pro_使用说明书.md>)核对，只描述既有操作，不构成刷写、配对或清设置授权。实际诊断应先完成构建与产物审查，再由用户决定设备操作。

1. **先松开所有键、退出 MEDIA，再切槽/传输。** MEDIA 中按 SYM 或物理右下 aA 回普通层；固件尝试向原目标发送 neutral，不保证断线主机收到松键。
2. **选目标蓝牙槽：** 从普通层按住物理右下 aA，再按通话 / 黑莓 P3 / 顶部物理返回 P5 / 结束，分别选择槽 **0 / 1 / 2 / 3**。槽从 0 计数；P5 是槽 2（第三槽）。按住右 aA 时，即使锁轮也优先选槽；松开右 aA 且锁轮时 P3/P5 的三击是滚轮固定档，勿混淆。
3. **选 BLE 输出偏好：右 aA + Q。** 这是 OUT_BLE 偏好，不能强迫未连接槽立即工作。选槽不等于选 BLE，插线也不等于 USB 输出；实际端点由 USB 就绪、活动槽连接与保存的输出偏好共同决定。记录实际端点，不能仅看灯或蓝牙名称推断。
4. **进入 MEDIA：按住 SYM，快双击 $，再松开 SYM。** 从首击按下起 **400ms** 内完成双击选择；进入后固定在 MEDIA，键盘灯为慢呼吸（亮度 0、关灯或 idle 可能使其不可见）。普通层直接双击 $ 只固定到 SYM，不是直接进 MEDIA。
5. **退出 MEDIA：仅 SYM / 右 aA 两个出口。** MEDIA 的 $ 是 A 按钮，不是退出；退出只恢复原内部路径，不解除本候选全局 BLE 键鼠禁用。

**不要用 UPPER 层 $ 双击尝试切 BLE。** 该双击虽是输出偏好切换，但其单击项是 bootloader；不够快、超时或被打断可能先进入刷机引导，且没有额外长按保险。优先用右 aA + Q。空槽配对、清旧配对均不在本文执行范围内。

## 3. 当前 MEDIA 全部位置：不套旧版键图

本候选保留[默认手册第 17 章](<9981Pro_使用说明书.md>)的 **19 个绑定＋2 个出口＋21 个 None＝42 个位置**。下表是逻辑功能；新 BLE 协议转换后的系统/App 映射仍未验证。

| 实体位置 | 当前 MEDIA 功能 |
| --- | --- |
| W / D / Z / A | D-pad 上 / 右 / 下 / 左（P8/P19/P28/P17），不是左摇杆 |
| S / L | L3 / R3（P18/P25），独立摇杆按键 |
| O / K / Backspace / $ | Y / X / B / A（上 / 左 / 右 / 下） |
| 通话 / 结束 | LB / RB（P2/P6） |
| 左肩 / 右肩 | LT / RT（P0/P1），数字 0/255，非模拟半按 |
| R / U | View / Menu（P10/P13） |
| 空格 / 触板机械按压 | 都是 Guide/Xbox；机械 DOWN 按下、UP 释放，不作 L3/R3 |
| 物理黑莓 | 按住临时切右杆，松开回左杆，不锁定 |
| SYM / 物理右下 aA | 回普通层的两个出口，尝试 neutral |
| 其余 21 位置 | None；包括 T/Y、E/X/F、顶部返回 P5、J、N、Enter，不发字母 |

尤其不要沿用旧版 E/X/S/F 方向、D/K 摇杆点击、I/J/L/M 面键或 T/Y 菜单映射。Guide 可能被系统或客户端截获，不能承诺传到远端。

### 触板与组合边界

- 默认滑动驱动左杆；MEDIA 中重新按住黑莓再滑动驱动右杆，松开回左杆。只有一个触板，不能同时独立控制两杆。
- 使用相对位移推算速度，不是实体杆或可靠触摸检测；停住手指不能保持杆倾斜，持续前进须继续滑动。原逻辑末次有效位移后 120ms 本地清轴，不等于主机在 120ms 内收到归中。
- MEDIA 不发鼠标、滚轮或轻拍；轻拍开关值不因进出 MEDIA 自动改变。候选退出后仍不会经 BLE 输出这些键鼠功能。
- 保留矩阵多键/鬼键风险。移动＋黑莓切杆＋开火、方向＋面键＋肩键均未在本候选实测；串键、误退出或卡键应记录具体组合并停止该项测试。

## 4. 沿用默认手册的功能与持久化

[默认手册](<9981Pro_使用说明书.md>)仍是四层全部默认键位和时序的依据：普通层第 3–9 章、SYM 第 10–12 章、UPPER 第 13 章、灯光/持久化第 15–16 章、维护第 18 章、触板杆第 26–27 章。保留控制不等于这些控制的蓝牙输出可用。

| 项目 | 保留规则与本候选限制 |
| --- | --- |
| 普通/SYM/UPPER | 层与键图不改；普通 Cmd/Ctrl、字母、SYM 音量等不会因绑定仍在而恢复 BLE 键盘/Consumer 输出 |
| 滚轮与鼠标翻转 | 右 aA 临时滚动、双击锁轮；右 aA＋M/P34 双击翻转仍为原控制；BLE 鼠标输出禁用 |
| 轻拍 | 普通层当前左键角色肩键快速三击开关（默认左肩，翻转后右肩）；重启 OFF，不持久化；MEDIA 阻断，BLE 鼠标禁用优先 |
| 指针增益 | 右 aA＋Z/P28 循环 0.6→0.9→1.2→1.5→1.8→0.6，首次 1.2；物理左下 Ctrl 半速；不是硬件 DPI，也不改变手柄杆增益 |
| 灯控 | 右 aA＋X/N 调键盘暗/亮、V 开关键盘；C/B 调触板暗/亮。MEDIA 键盘约 3.6 秒慢呼吸，不能凭灯认定系统已接收手柄 |
| 保存 | 两套亮度与指针档独立保存；末次调节后至少等 1 秒再断电。失败/中途断电不保证保存；本候选断电恢复未验证 |
| 非持久状态 | 轻拍、锁轮、鼠标翻转重启复位；本候选未新增“纯 BLE 模式”持久化或运行时模式选择 |
| 输出与配对 | 原输出偏好、槽与 Studio 设置规则保留；未新增身份切换或清配对。已保存 Studio 改键可能覆盖默认值，不能据此擅自擦设置 |

维护危险键仍在 UPPER：R 单击重启、T 切外设供电、触板机械双击清当前槽、$ 单击进入 bootloader、$ 双击切输出偏好；触板机械单击仍为左键逻辑、E 为 Eject。**BLE 禁用不等于危险键失效，也不把清配对、settings_reset 或擦闪存作为普通排错。**

## 8. PnP编号来源对照：已构建、有用户测试反馈

- 旧P1实际上以Source=1（蓝牙SIG分配命名空间）发送 `1D50:615E`，而该数值为OpenMoko公开登记的ZMK USB VID/PID。对照源码只把来源改为2（USB-IF命名空间），保留相同 VID/PID，不冒充其他厂商；但它仍是**蓝牙身份元数据变化**。
- 对照保持旧P1的唯一HIDS、描述符、键位与USB源码配置；其蓝牙键盘、Consumer和鼠标仍全局关闭。它不是可切换的三合一，也没有宣称能解决苹果识别。
