2026-10-22；候选分支 `codex/pointer-steady-v2.3.2-20261022`。功能源码：`1124252fcd43375a27b826224747121ba78e06a2`。精确基线为v2.3.1封版 `cee926aa736e6f4f01278212c727e3e73f2403d1`；原重构BASE及USB加固基线不换。

## 只改变普通鼠标输出

链路为：RAW → 历史单帧削峰 → 逐轴一计数滞回 → 原1.2/0.6小数增益 → 原方向翻转/输入通道。轻拍资格仍用原始RAW与旧影子pointer；滚轮、虚拟杆、键位、灯光、设置、描述符、轮询线程和v2.3.1 USB修复不变。

### 1. 小位移防抖

每轴 `acc += raw`；仅当 `|acc| > 1`，发出 `acc - sign(acc)`，保留 `sign(acc)`，否则不移动。零输入绝不消费余量，逐轴超过50ms没有非零输入清余量。

- ±1交替不再来回出位移；持续同向±1首帧后逐帧续发，原小数增益仍累计。
- 不生成惯性、追赶补偿或停手尾巴，不新造原本为0的轴，不反发旧方向。
- **不是完全无损。** 起步保留1RAW/轴；反向先抵消旧余量，再建立新余量，例如 `+1,-1,-1,-1` 发 `0,0,0,-1`，微调反向会有死区。正常连续段的有符号累计误差只等于±1以内余量；绝对路径不承诺每次反向只损1。空闲/模式/故障重置会丢弃余量。

### 2. 历史黏滑突刺削峰

保存4个**RAW**最大轴速度，按10ms归一；全都≤2计数/10ms时才限本帧，`cap=max(ceil(6*dt/10),ceil(norm/2))`，各轴同比例对称舍入。原始速度入历史，所以连续快滑下一帧立即绕过削峰。重复时间戳或间隔>50ms清历史，当前帧透过此级再进防抖。

削掉的位移直接丢弃，不排队偿还；**故意从慢移突然快滑也可能被削弱**。这是一种材料黏滑启发式，不是传感器接触检测，也不保证所有物理抖动消失。

### 3. BLE只减少已有积压突发，不增加等待

在首次SDK尝试前，只合并FIFO中已经存在的紧邻普通纯XY：同captured conn指针、同buttons，距首项入队0–10ms，64位叉积为0且点积>0，XY求和在int16范围。保留首项最早400ms TTL，不滑动窗口。

零XY、每份按钮快照、全部滚轮/混合报告、按钮变化、peer/重连对象、拐角、反向、溢出均是硬屏障。失败重试或SDK正在使用的head不再改写；不新增timer、workqueue或节流等待，原10ms重试/40次/400ms、满队列拒绝及连接清理保留。

每吸收一项减少outstanding、增加coalesced，该项一次conn引用在锁外、SDK前释放；SDK等待期间即使生产者重新补满，后续清理数组也不会叠加两批。账本为 `accepted = notified + canceled + coalesced + outstanding`。

**这不是固定10ms发送，也不是屏幕绝对匀速。** 主机加速度、无线资源和系统调度仍会影响显示；合并的逻辑位移总和不等于主机加速后屏幕轨迹严格相同。轻拍原有候选缓冲仍可能在同轮回放，不声称开/关轻拍延迟一致。

## 故障与上下文

速度、方向、滚轮/gamepad epoch、主机切换和传感器故障清新滤波状态。实际回放按原采样时间，不拿同轮回调墙钟代替多个历史时间。

独立复核发现并修复一处边界：微移候选在I2C/GPIO故障后若再回放，会重新污染刚清零的削峰历史，故障恢复首帧可能被错误减半。**新feature下传感器故障通过既有context取消路径丢弃尚未提交的候选/回放**，不会把故障前缓存带到新epoch；已由bridge持有的必要按钮UP仍按原路径处理，不释放foreign引用。正常拒绝候选回放和RAW轻拍阈值不变。
