# v2.3.4：BLE单主机连接候选

日期：2026-10-24。基线为v2.3.3工作树提交`432d6c857382769963afd65de0f803a303a67e59`。功能提交、实际构建、UF2身份与软件验证结果统一见[当前交付记录](<../firmware-delivery/XBOX_CURRENT.md>)；本文不把尚未完成的构建或无线实机测试记为通过。

## 为什么做，与此前iPad问题的区别

用户报告清理所有蓝牙槽、重新建立配对后，旧版和新版均可在iPad使用。这个结果支持持久配对/身份/HID会话状态曾不一致，但不能仅凭恢复区分密钥、重复槽记录、服务缓存或其他状态。此前BLE槽0 ready的心跳不包含加密等级、报告订阅或主机收包证据。

ZMK本来允许旧主机保持BLE连接，只向当前活动槽发送输入。用户随后明确选择改为单主机连接候选。本轮是该使用行为的改变，**不是已证实的iPad故障根因修复，也不证明默认多连接本身就是错误**。

## 用户可见行为

- 选槽快捷键不变：普通层按住右aA，再按通话/黑莓/顶部返回/结束，分别选槽0/1/2/3。按住aA时的选槽优先级不改。
- 切槽后调和全部已连接的入站主机，主动请求断开非当前槽主机。后续连接、身份解析、安全状态和活动槽事件都会按最新目标重判，不只断一次。
- 已保存配对不自动删除；切回原槽仍可重连。已属于其它槽的旧主机不能抢占当前空槽；真正未知的新主机可在所选空槽按原流程配对，空槽至多保留一个临时候选。
- 配对请完成后再切槽。配对中切槽、候选被拒或取消/失败时，不把它写入新的活动槽，也不主动擦除既有bond；该次未完成配对可能需要重新发起。原生栈已产生的新bond与profile记录并非原子事务，不承诺所有异常自动恢复。
- 当前peer地址优先于旧槽的首个匹配，因此历史同peer多槽不会仅因首匹配而把当前主机误踢；但不自动去重或修复历史槽记录。日常一台主机使用一个槽，不把全清当常规切换。
- 单主机不是单配对槽。多个槽的记录仍可保留，但不再为快速切换长期保持多台电脑/手机同时在线。
- USB连接、USB/蓝牙输出偏好、HID描述符与全部168个默认绑定不变。选择USB输出不等于关闭当前BLE连接；Studio优先走USB，非当前主机的BLE连接也会受本策略影响。
- BLE CENTRAL角色的外设/分体连接、非默认本地身份、非LE连接不受管理；split-peripheral构建整项关闭。

## 明确的保证边界

这不是链路层白名单。未启用控制器accept list，也未把广播改为定向广播，以免控制器身份解析容量/隐私地址兼容差异将当前iPad挡住。旧主机仍可发起连接尝试，可能短暂显示已连接；被识别为非当前主机后再次请求断开。

断开是异步的。已提交的断开不能撤销，A→B→A快速切回时A仍可能先断后重新连接。不能保证瞬间绝对单连接、零旧尾包、固定N毫秒重连，或主机UI立即更新。已有键鼠异步队列和端点清报告语义未重构。

未知且尚未解析的RPA在已占槽最多宽限1000ms，等待身份/安全事件后重判；正常空槽新配对不使用该超时。使用SDK的连接身份目的地址而非空口地址，不靠主机名称识别设备。这是软件策略，不是iPad无线实测认证。

断开/信息查询失败按50ms间隔最多3次尝试；不忙循环、不清配置、不写新设置。错误耗尽后由新的相关事件、切到另槽再切回或正常重启重新尝试。栈不完成断开、工作队列饥饿或持续控制器错误时没有墙钟完成保证。

## 实现与范围

新增一个`CONFIG_BBP9981_BLE_SINGLE_HOST`开关，产品候选启用，默认Kconfig为n。策略服务和对固定BLE源的auth注册前缀仅在ON、BLE启用且不是split-peripheral时链接。OFF完全保留stock服务/回调行为，不是把所有连接强制关闭。

生产仅3份精确追加：主配置、板级Kconfig、板级CMake；另增5份策略/前缀/构建与SDK闸文件。85份旧配置中82份保持原字节；历史投影精确恢复v2.3.3后继续进入原v2.3.3/v2.3.2/重构/封版验证链，所有既有C oracle和SDK fixture保持原字节。未改键图、GPIO、传感器、指针、滚轮、轻拍、手柄、灯光、USB实现或设置格式。

auth前缀只替换固定BLE TU的两个注册函数，保留正常回调委托，避免已知旧peer在空槽重新配对，以及配对中切槽导致错写新槽或进入stock不允许分支的unpair。合法complete最终门检查起使用短scheduler锁；固定源码在捕获profile参数前无阻塞，原settings后端如阻塞，参数已捕获。此约束依赖已审查SDK及单核线程上下文，不宣称覆盖ISR选槽或未知SDK变化；无IRQ/spin锁跨BT/设置调用。
