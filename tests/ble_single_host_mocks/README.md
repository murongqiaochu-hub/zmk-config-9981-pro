# Single-host BLE host-test boundary

The complete [BLE translation unit](<sdk_v0_3_0_ble.c>), [public BLE API](<zmk/ble.h>), [profile structure](<zmk/ble/profile.h>) and [profile event](<zmk/events/ble_active_profile_changed.h>) are original bytes from ZMK v0.3.0, commit `edf5c0814fd3ea202e43aad2d68fd32e882a518c`. [Fixture identities](<fixtures.json>) record upstream paths, byte lengths, Git blob SHA-1 and SHA-256. They were downloaded directly from [the fixed upstream commit](<https://github.com/zmkfirmware/zmk/tree/edf5c0814fd3ea202e43aad2d68fd32e882a518c>), not reconstructed from an abbreviated source excerpt. Do not edit them to make a test pass.

[The environment header](<test_env.h>) and [implementation](<test_env.c>) are deterministic mocks, **not** SDK fixtures. The runner creates empty include seams only inside its private build directory; immutable official headers above take precedence. The real SDK translation unit, production policy service, and test driver compile as separate translation units. Only the production auth-registration prefix is force-included into the SDK source, exactly as firmware integration requires. Tests never assign SDK private profile/advertising variables and never call SDK static functions. SYS_INIT, BT_CONN_CB_DEFINE, ZMK_LISTENER, settings handlers and auth callback registration are captured by mocks and invoked through their public registration seams.

The fake work scheduler is deferred and chronological; a zero-delay storm or unbounded delayed retry trips a hard guard. A successful disconnect request changes state to DISCONNECTING; it is not a completion or host acknowledgement. The test must explicitly emit disconnection. Identity addresses and raw RPAs are distinct, and identity/security callbacks are explicit. Connections have base references and instance serials, allowing index-reuse and reference-balance assertions. Settings mocks only accept stock `ble/` saves; unpair/delete calls are counted and forbidden in normal policy cases.

Run `python3 -B tests/run_ble_single_host_tests.py` from the project root. `--baseline-only` checks the stock fixture before the production service is available. All artifacts stay below `.host-test-build/ble-single-host/`; this runner does not run the full host suite, access a Bluetooth controller, alter settings, perform an ARM build, push or flash.

The policy intentionally does not implement FAL/directed advertising or alter stock advertising. Tests cover bounded disconnection of identified inactive host peers, not controller-level rejection before connection. Brief connections, unresolved privacy identities during the grace interval, delayed host UI, real radio delivery, real-time scheduling, hardware pairing migration, ARM linking, and device acceptance remain outside this host model. Unknown pairing interrupted by a slot change may be conservatively rejected; no existing bond may be erased as a consequence.
